# VisionaryX 2.0.0: the revival

Released 2026-10-31 · tag [`v2.0.0`](https://github.com/siddhant-17-codes/VisionaryX-2.0/tree/v2.0.0) (commit `150448f`). These are the notes for the GitHub release; paste everything below the next line.

---

VisionaryX is an AI workspace that cites its sources: ask questions across PDFs and Word
files and every answer names the file, page or section it came from. It also answers
questions about images and generates new ones. Live at https://visionaryx-dusky.vercel.app.

By October 2026 the live demo was broken: the free Supabase project had paused, Hugging
Face had retired the free FLUX endpoint, an old backend on another account still held the
project's keys, and every visitor could see every other visitor's conversations. This
release is the audit and repair of the whole stack, one branch per area, each merged with
CI green.

## Highlights

- **Private history without accounts.** Each browser gets an anonymous ID; the backend
  stores only its SHA-256 and shows each browser only its own chats. Someone else's chat
  answers 404, exactly like a missing one. Row-level security is on in Supabase.
- **Citations that name the file.** With several documents, each source card shows the
  file and the PDF page or the Word heading. Word tables are read; `.doc` is refused.
- **It degrades instead of failing.** Gemini calls fall back from `gemini-2.5-flash` to
  two lite models when quota runs out, errors are typed by HTTP status, and the UI shows
  which model answered.
- **Image generation is back,** on Cloudflare Workers AI (FLUX.1 schnell) with Hugging
  Face as fallback, an honest "paused until …" state when the free allowance is used up,
  and at most 20 images per visitor per day.
- **Safer storage.** Search indexes are stored as JSON instead of pickle; indexes saved
  before still load through a data-only reader that cannot run code.
- **Hardening.** CORS allow-list, per-IP rate limits, upload size limits, timeouts on
  every upstream call, and route handlers off the event loop (one upload used to freeze
  the server for 14 s).
- **It stays up.** `/health/db` plus a keep-alive workflow every three days, a notice
  while the free backend wakes up, and deep links that work on Vercel.
- **UI.** WCAG AA text contrast, keyboard and screen-reader access, a mobile layout that
  fits the screen, markdown that keeps inline code and numbered lists, answers revealed
  in about a second.
- **Engineering.** Python 3.12, `google-genai` instead of the deprecated SDK, a fully
  locked dependency tree (torch and CUDA no longer installed), 123 backend and 53
  frontend tests at the time of the release (every audited bug went in first as a strict failing test), CI on every
  push, POSIX Makefiles, `schema.sql` and complete `.env.example` files.
- **Docs.** A new README with architecture, how RAG and citations work, eight
  engineering decisions, a local setup tested from a fresh clone, and a demo recorded
  from the live site.

## Deploying this release yourself

1. Run `supabase/schema.sql` in a new Supabase project (an existing 1.x database: run
   `backend/migrations/001_session_ownership.sql`, one section at a time).
2. Set `GOOGLE_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `ALLOWED_ORIGINS`
   (required, must not be empty), `HUGGINGFACEHUB_API_TOKEN`, and optionally
   `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN`; see `backend/.env.example`.
3. Python 3.12 on the backend; `VITE_API_URL` on the frontend.

## Known limits

Free tiers throughout: the backend sleeps after 15 minutes idle (the first request then
takes about a minute), about 20 answers a day come from `gemini-2.5-flash` before lite models take
over, about 170 images a day are shared by all visitors, and history lives in the
browser that created it.
